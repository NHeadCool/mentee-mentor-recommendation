# Mentee-Mentor Recommendation API

Проект для тестирования рекомендательной системы подбора IT-менторов для менти в условиях, когда нет реальных пользовательских данных и истории успешных матчей.

Система работает с симулированными JSON-профилями менти и менторов. В текущей версии реализованы два способа получения рекомендаций:

1. **Candidate selection + YandexGPT**: сначала из общего пула менторов алгоритмически выбираются 20 наиболее релевантных кандидатов, затем YandexGPT ранжирует только этих кандидатов и возвращает top-N с объяснениями.
2. **Personalized PageRank**: отдельный алгоритм строит граф из менти, менторов и общих признаков профилей, после чего возвращает top-N без обращения к LLM.

Также есть веб-интерфейс для выбора менти, запуска алгоритма и просмотра карточек рекомендованных менторов.

## Цель проекта

Цель проекта - проработать техническую часть рекомендательной системы для сервиса менторства:

1. определить характеристики профилей ментора и менти на основе анализа конкурентов и исследовательского интервью;
2. сгенерировать тестовые профили с разной степенью заполненности;
3. реализовать объяснимые рекомендации через YandexGPT;
4. добавить предварительный отбор кандидатов перед отправкой профилей в LLM;
5. реализовать альтернативный алгоритм Personalized PageRank;
6. сравнивать качество рекомендаций на полных, средних и низко заполненных профилях.

## Реализованный подход

### Подход 1. Candidate selection + LLM-ranking

YandexGPT не получает весь пул менторов. Перед вызовом LLM выполняется предварительный отбор:

1. пользователь выбирает одного менти;
2. API загружает весь пул менторов из `data/mentors.json`;
3. `LLMCandidateSelector` запускает Personalized PageRank по всем менторам;
4. из общего пула выбираются до 20 кандидатов;
5. в YandexGPT отправляются профиль выбранного менти и только эти 20 кандидатов;
6. YandexGPT выбирает top-N менторов, формирует оценку, объяснение, совпавшие факторы и возможные риски.

Это снижает размер промпта, уменьшает время ответа и повышает вероятность того, что в LLM попадут релевантные профили, а не первые записи из JSON-файла.

Лимит кандидатов задан в `app/services/llm_candidate_selector.py`:

```python
DEFAULT_LLM_CANDIDATE_LIMIT = 20
```

В ответе YandexGPT-эндпоинта сохраняется техническая информация об отборе кандидатов:

```json
{
  "raw_model_response": {
    "candidate_selection": {
      "algorithm": "personalized_pagerank",
      "input_mentors_count": 1015,
      "candidate_limit": 20,
      "selected_mentors_count": 20,
      "selected_mentor_ids": ["mentor_control_pm_transition"]
    }
  }
}
```

### Подход 2. Personalized PageRank

Personalized PageRank используется как самостоятельный алгоритм рекомендаций и как предварительный отбор кандидатов для YandexGPT.

Алгоритм строит граф из:

- выбранного менти;
- всех менторов;
- общих признаков профилей: целевая роль, навыки, индустрия, формат, язык, уровень, бюджет, доступность, часовой пояс;
- признаков надежности и качества профиля: рейтинг, количество сессий, полнота профиля, скорость ответа, доля отмен.

Персонализация задается признаками выбранного менти. В результате выше поднимаются менторы, связанные с теми же признаками графа.

Ответ Personalized PageRank имеет тот же формат `RecommendationResponse`, что и YandexGPT-эндпоинт: список рекомендаций, score, объяснение, совпавшие факторы и возможные риски.

## Исследовательская основа

Для проекта были использованы:

- анализ конкурентов и признаков, которые встречаются в сервисах менторства;
- открытое интервью о менторстве в IT, онбординге, развитии компетенций и роли наставника.

Интервью помогло уточнить контекст, который важно учитывать при проектировании профилей и объяснений:

- менторство бывает разным: онбординг, помощь с рабочими задачами, развитие конкретных компетенций;
- результат менторства можно оценивать через рост самостоятельности менти;
- стиль помощи зависит от срочности задачи: иногда нужен быстрый готовый ответ, иногда - сопровождение через вопросы и документацию;
- мотивация менти и готовность работать с обратной связью влияют на эффективность взаимодействия;
- совпадение контекста, инструментов и формата взаимодействия может быть важнее простого совпадения должности.

Эти выводы используются как исследовательская база для выбора признаков профиля, объяснений рекомендаций и списка возможных рисков.

## Данные

В проекте используются два основных JSON-файла:

```text
data/mentees.json
data/mentors.json
```

Текущий объем сгенерированных данных:

- `1202` профиля менти;
- `1015` профилей менторов.

Файлы содержат симулированные профили с разной степенью заполненности:

```text
profile_completeness = high
profile_completeness = medium
profile_completeness = low
```

Распределение по заполненности:

| Тип профиля | high | medium | low |
|---|---:|---:|---:|
| Менти | 481 | 360 | 361 |
| Менторы | 405 | 307 | 303 |

Это нужно для тестирования того, как алгоритмы меняют рекомендации и объяснения в зависимости от полноты данных.

### Примеры контрольных профилей

```text
mentee_control_pm_transition
```

Контрольный кейс: аналитик хочет перейти в Product Manager.

```text
mentor_control_pm_transition
```

Ожидаемо релевантный ментор для этого кейса.

```text
mentee_control_low_info
```

Контрольный кейс с низкой заполненностью профиля: почти только свободный текст про неудачные собеседования.

```text
mentor_control_career_interview
```

Потенциально релевантный ментор для кейса с собеседованиями и резюме.

## API

### Получить рекомендации от YandexGPT

```text
POST /api/v1/recommendations/yandex-gpt/from-json
```

Пример запроса:

```json
{
  "mentee_id": "mentee_control_pm_transition",
  "top_n": 5
}
```

Что происходит внутри:

1. API загружает выбранного менти и всех менторов.
2. Personalized PageRank выбирает до 20 кандидатов из общего пула.
3. YandexGPT получает только выбранные 20 профилей.
4. YandexGPT возвращает не больше `top_n` рекомендаций.

Пример ответа:

```json
{
  "mentee_id": "mentee_control_pm_transition",
  "recommendation_logic": "Модель выбрала менторов на основе совпадения цели, навыков, опыта, формата и доступности.",
  "recommendations": [
    {
      "mentor_id": "mentor_control_pm_transition",
      "mentor_name": "Иван Контрольный",
      "rank": 1,
      "score": 95,
      "explanation": "Ментор подходит, потому что помогает аналитикам переходить в product management.",
      "matched_factors": [
        "совпала целевая роль",
        "совпали навыки product discovery и roadmap",
        "совпал формат регулярных созвонов"
      ],
      "possible_risks": [
        "ограничение по бюджету"
      ]
    }
  ],
  "general_explanation": "Наиболее релевантные менторы выбраны по совпадению профессиональной цели, экспертизы и формата работы.",
  "raw_model_response": {
    "candidate_selection": {
      "algorithm": "personalized_pagerank",
      "input_mentors_count": 1015,
      "candidate_limit": 20,
      "selected_mentors_count": 20
    }
  }
}
```

### Получить рекомендации через Personalized PageRank

```text
POST /api/v1/recommendations/personalized-pagerank/from-json
```

Пример запроса:

```json
{
  "mentee_id": "mentee_control_pm_transition",
  "top_n": 5,
  "damping_factor": 0.85,
  "max_iterations": 120,
  "tolerance": 1e-8
}
```

Алгоритм строит граф из выбранного менти, всех менторов и общих признаков:
целевой роли, навыков, индустрии, формата, языка, уровня, бюджета, доступности,
часового пояса и признаков надежности.

В `raw_model_response` возвращается техническая информация:

- количество узлов и ребер графа;
- количество использованных менторов;
- число итераций;
- флаг сходимости;
- сырые PageRank-score для top-N.

## Интерфейс

В интерфейсе можно:

1. выбрать менти из списка;
2. посмотреть его характеристики;
3. указать количество рекомендаций;
4. выбрать алгоритм: `Personalized PageRank` или `YandexGPT`;
5. нажать кнопку `Сделать рекомендацию`;
6. получить карточки рекомендованных менторов;
7. посмотреть объяснение, почему выбран именно этот набор менторов.

Для YandexGPT-интерфейс дополнительно показывает, сколько кандидатов было отправлено в LLM из общего пула, например:

```text
Отправлено в YandexGPT: 20 из 1015
```

Интерфейс нужен для удобного анализа результатов без чтения сырого JSON.

## Связь с анализом конкурентов и интервью

В конкурентном анализе были выделены ключевые признаки, которые часто используются сервисами менторства:

- цель менти;
- текстовый запрос или проблема;
- навыки;
- опыт;
- уровень;
- формат взаимодействия;
- доступность;
- часовой пояс;
- язык;
- бюджет;
- отзывы и надежность;
- коммуникационные предпочтения.

Открытое интервью добавило к этим признакам контекст менторского взаимодействия:

- сценарий помощи: онбординг, рабочая задача, развитие компетенции;
- степень самостоятельности менти;
- мотивация и готовность принимать обратную связь;
- срочность запроса;
- стиль помощи: прямой ответ, сопровождение через вопросы, работа через документацию, проектное сопровождение;
- критерий результата: менти начинает самостоятельно решать задачи своего уровня.

Текущая реализация пока использует не все эти признаки как отдельные поля, но они учитываются при проектировании профилей, промпта, объяснений и списка возможных рисков.
